# Waitlist Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `apps/waitlist`, a pixel-art Next.js site where a visitor signs in with X, confirms four honor-based X tasks, binds a wallet by signature, joins the list, and downloads/posts a share card.

**Architecture:** Next.js App Router. All logic lives in `src/server/*` service modules that take a `Deps` object (`db`, `clock`, `x`, `newCode`), so Vitest drives them against PGlite with a fake X client; route handlers in `src/app/api/**/route.ts` are thin adapters that call `getDeps()` and a service. Persistence is Drizzle over Postgres (`pg` in prod, PGlite in tests/dev), mirroring `apps/server/src/db/client.ts`. Art is chosen only through `src/art/slots.ts`; every sprite has a flat element-colour fallback, so code tasks never wait on art.

**Tech Stack:** Node 24, TypeScript 5 strict, Next.js 16, React 19, drizzle-orm + drizzle-kit, `@electric-sql/pglite`, `pg`, zod, jose 6, viem 2, wagmi 3 + `@reown/appkit` + `@reown/appkit-adapter-wagmi` + `@tanstack/react-query`, `next/og`, Vitest, `@testing-library/react`, Playwright (`@playwright/test`). Use versions current at install time; respect the workspace `minimumReleaseAge`.

**Spec:** `docs/superpowers/specs/2026-10-29-waitlist-design.md` (all sections). Game identity: `docs/superpowers/specs/2026-10-28-wyrmhaven-design.md` §1–3.

## Global Constraints

- Work only inside `apps/waitlist` (plus this plan). Another thread works in `packages/`, `contracts/`, `apps/server`: stage files by path (`git add apps/waitlist/...`), never `git add -A`, never rebase/reset/amend, never push.
- Package name `@wyrmhaven/waitlist`; scripts `dev`, `build`, `start`, `test` (vitest run), `typecheck` (tsc --noEmit), `test:e2e` (playwright). `pnpm -r test` must not run Playwright.
- Elements, in this order: `fire, water, earth, nature, electric, ice, metal, dark, light`. Starting element = `ELEMENTS[sha256(xUserId)[0] % 9]`.
- Tasks: `follow, like, repost, comment`. Confirm is accepted only when `now − openedAt ≥ 15 000 ms`.
- X accounts younger than `MIN_X_ACCOUNT_AGE_DAYS` (default 30) are refused.
- Session cookie `wh_session` (jose HS256, `{ sub: entrantId }`, 30 days, httpOnly, secure in prod, sameSite lax). OAuth cookie `wh_oauth` (`{ state, verifier, ref? }`, 10 min).
- Signed wallet message, exact text: `Wyrmhaven waitlist\nX: @<handle>\nAddress: <0x… checksummed>\nNonce: <nonce>`. Nonce single-use, 10-minute expiry. Wallet stored lowercase.
- Errors: JSON `{ error: CODE }`. Codes: `UNAUTHORIZED` 401, `X_ACCOUNT_TOO_NEW` 403, `TOO_EARLY` 409, `TASK_NOT_OPENED` 409, `NONCE_INVALID` 400, `INVALID_SIGNATURE` 400, `WALLET_TAKEN` 409, `TASKS_INCOMPLETE` 409, `WALLET_REQUIRED` 409, `RATE_LIMITED` 429, `BAD_REQUEST` 400. Bodies parsed with zod.
- Secrets only from env; commit `.env.example`, never `.env`. No promises of earnings, token price, airdrops or allocations anywhere in copy.
- Art prompts describe our own designs and never name another game or its style.
- Pixel rendering: integer scaling only, `image-rendering: pixelated`; animations play with CSS `steps()`; `prefers-reduced-motion` shows frame 0.

## Review Focus

1. The same X account finishes OAuth in two browsers at once → exactly one entrant (upsert on `x_user_id`); returning later with a changed handle/avatar updates them and keeps position and ref code. (Task 3)
2. A wallet signature with a reused, expired or other-entrant nonce, or signed for a different handle or address, is refused and binds nothing. (Task 5)
3. Double-clicked or concurrent Join → one position, and a repeat Join returns the same position. (Task 6)
4. OAuth callback with `error=access_denied`, a mismatched `state`, or no `wh_oauth` cookie → redirect to `/?x=denied#join` (or `x=error`) with no entrant created. (Task 7)
5. The X avatar URL fails to load while rendering the card → the card still renders, with the hatchling sprite in the avatar spot. (Task 9)
